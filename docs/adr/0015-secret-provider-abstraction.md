# ADR-0015: Secrets through a SecretProvider

## Context
The stack needs secrets: the authorization server's RSA signing key, the notification and CRM API keys. They must
not be committed, logged or passed through tool arguments.

## Decision
- `SecretProvider` interface with `get(name) -> str`. Implementations: `EnvSecretProvider`
  (`SECUREMCP_SECRET_<NAME>`, development) and `FileSecretProvider` (one file per secret in
  `SECUREMCP_SECRETS_DIR`, matching Docker/Kubernetes secrets mounted at `/run/secrets`).
- Compose mounts secrets generated by `make secrets` (`deploy/secrets/`, git-ignored).
- Secret values are wrapped in `pydantic.SecretStr` in memory, so accidental `repr`/logging shows `**********`.

## Alternatives considered
- **Plain environment variables everywhere**: visible in `docker inspect`, process listings and crash dumps.
- **Vault / AWS Secrets Manager client now**: right for production, unnecessary for a local stack; the interface
  makes it a drop-in.

## Consequences
- In development, missing secrets for the mocks fall back to generated values only when `SECUREMCP_ENV=dev`;
  in `prod` a missing secret fails startup.
